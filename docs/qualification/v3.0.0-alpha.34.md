# Alpha34 upgrade workflow and SDK qualification

Release sequence: `2739`. Native ABI: `6`. MicroPython: `1.29.0`.
ESP-IDF: `5.5.5` (changed from `5.5.1`).

The optional `tests/browser_upgrade_workflow.py` Playwright regression uses local
fixtures and the real portal CSP at desktop and mobile widths. Run from the
repository root; set `CHROME_BIN` to a browser executable or install Playwright's
Chromium. It checks milestone alignment, form containment, method availability,
version/file selection, completed rings and inline release-check navigation.

## Portal checks

1. Open Maintenance > Upgrades > Upgrade. There must be no intermediate summary
   page. Automatic and Manual are methods in the same workflow; show Rollback
   only with a previous application and Staged only with a verified release.
2. On desktop confirm horizontal circles, labels above, no horizontal scrollbar
   and all actions within the card. Check a narrow mobile screen as well.
3. Automatic: check for upgrades inline, select a compatible version and confirm
   the milestones match Universal, Application or Core. Check again with no newer
   release and with an unavailable release server; neither result needs a percent.
4. Manual: select each supported file type and confirm the correct milestones.
   Reject an invalid file and recover to selection without a stuck Working state.
5. Stage an automatic universal release and separately a manual one. Switch tabs
   during transfer, return, and refresh during the device-side task. Check circular
   progress and that the number of milestones does not shrink after staging.
6. Leave a release staged, navigate away, return and select Staged. Verify Restart
   is explicit. Discard staging and confirm a new release can then be selected.
7. Exercise the retained application rollback path on a test device; it must
   accurately state that it does not change the core version.

## ESP-IDF 5.5.5 device checks (required, not implied by host tests)

- Install the universal package and verify both core and application Alpha34.
- Confirm paired trial acceptance and paired rollback on failed trials; repeat
  power interruption at staging, activation and confirmation transitions.
- Repeat cold boot and power-cycle recovery, Wi-Fi loss/reconnection, MQTT and
  Home Assistant reconnect, HTTPS portal and mTLS API, syslog and certificate
  enrollment/renewal/trust rejection checks.
- Exercise configured GPIO/ADC/UART/I2C/SPI modules, calibration persistence,
  storage pressure, soft restart and native recovery.
- Complete the release's soak, health, storage and canary gates. Preserve actual
  evidence; do not infer success from a green host build.
