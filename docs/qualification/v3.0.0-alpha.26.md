# IoT-MD v3.0.0-alpha.26 constrained activation and upgrade UI test

Alpha 26 uses release sequence `2731` and native platform ABI 6.

1. From Alpha 24, configure the Alpha channel and select **Check for upgrades**.
   Confirm the task finishes with **Release available** and no terminal
   percentage.
2. Select **Download and stage**. Confirm the release is identified as a
   universal upgrade and that both components are verified.
3. After returning to Upgrades, confirm there is one **Staged upgrade** panel,
   no duplicate available-release banner and the action reads **Activate
   universal upgrade 3.0.0-alpha.26 and reboot**.
4. Activate the release. Confirm the device does not roll back for insufficient
   application-slot storage and Overview reports both Application version and
   Core version as `3.0.0-alpha.26`.
5. Open **Maintenance > Release qualification** and confirm the recorder is
   available and its cross-release evidence remains present.
6. With no staged release, confirm Upgrades presents release-channel and local
   file choices together and keeps automatic settings collapsed by default.
7. Run **Check for upgrades** again. Confirm the completed task reports **No
   newer release** without `100%` and returns to Upgrades.
8. Power-cycle the device once and confirm it returns with a green status LED,
   both version values unchanged and no orphaned universal transaction.
