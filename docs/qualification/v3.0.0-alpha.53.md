# Alpha 53 API scope-management test

Alpha 53 uses release sequence `2758` and native platform ABI 6.

Status: **host regression passed; awaiting device evidence**.

## Purpose

Verify that an administrator can add qualification permissions to an existing
mTLS API client without duplicating or replacing its certificate record, then
use that identity for controlled watchdog qualification.

## Procedure

1. Install the signed Alpha 53 application over the confirmed Alpha 52 pair.
2. Open **Device > Device API**, expand **Edit API scopes** on the existing
   automation client, and add `qualification:write` and
   `qualification:execute` while retaining its required routine scopes.
3. Save and confirm that the fingerprint, label, subject, issuer, expiry and
   enrolled-client count are unchanged. Reopen the editor and confirm every
   selected scope remains selected.
4. Repeat the inspection under **Maintenance > Certificates > API client
   trust** and confirm both pages expose the same scope set.
5. Using that certificate and private key, confirm an authorised qualification
   API read succeeds and a deliberately unselected operation receives `403`.
6. Run one controlled watchdog exercise with a unique run ID. Retain serial
   output and verify a higher boot count, watchdog reset cause and healthy
   return before recording the observation.
7. Export qualification evidence and confirm that merely requesting the
   watchdog scenario did not increment the gate; only the observed recovery
   may be submitted as evidence.

The broader Alpha 52 qualification requirements remain applicable. Alpha 53
changes the application sequence, so release-bound soak, health, storage,
canary and confirmation evidence must be collected against sequence 2758.
