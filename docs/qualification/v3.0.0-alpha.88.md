# v3.0.0-alpha.88 universal retry reconciliation

## Automated evidence

- Retrying a retained universal plan re-reads both installed release sequences.
- An equal installed component becomes satisfied and is not uploaded again.
- A failed missing component receives a new upload identifier on retry.
- A component newer than the signed pair remains downgrade-protected.
- The incomplete-pair portal state prevents independent component activation.
- Application, MicroPython compatibility and architecture tests pass.

## Field verification

1. Stage only the core from a universal pair and interrupt application staging.
2. Install the staged core and allow the device to return.
3. Retry the same universal file.
4. Confirm core transfer is skipped and application staging begins.
5. Confirm the application/core pair reaches `confirmed` without a same-sequence
   firmware rejection.
