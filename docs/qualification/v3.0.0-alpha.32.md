# IoT-MD v3.0.0-alpha.32 IoT CA renewal-key test

Alpha 32 uses release sequence `2737` and native platform ABI 6. It corrects
the renewal-key representation used by both immediate and scheduled IoT CA
renewal.

## Focused device test

1. Upgrade an IoT CA-enrolled device to Alpha 32 and confirm Application
   `3.0.0-alpha.32`. A core update is not required for this correction.
2. Record the current portal and Device API certificate serial numbers and
   expiry dates.
3. Select **Renew now** under **Maintenance > Certificates > Device
   certificates**. The request must start without the `IoT CA renewal private
   key is invalid` error.
4. Wait for the reconnectable certificate-renewal task to complete. Confirm
   that the portal and Device API identities have new serial numbers, valid
   chains and the expected hostnames.
5. Confirm that HTTPS, the mTLS Device API and MQTT reconnect, and that Health
   history records `certificate_renewed` without exposing private key data.
6. Restart the device and repeat the certificate and service checks. Do not
   force another renewal unless IoT CA policy permits it.

Record actual observations in the qualification evidence. A passing host test
suite is not device evidence.
