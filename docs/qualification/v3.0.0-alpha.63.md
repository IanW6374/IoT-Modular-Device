# Alpha 63 portal workflow qualification

Alpha 63 uses release sequence 2768 and native platform ABI 6.

Status: **host regression passed; awaiting device evidence**.

1. Upgrade a healthy Alpha 62 device to Alpha 63 using the universal artifact.
2. Confirm the top-level navigation and current page remain stable after saving
   Network, Portal, Time/Date, MQTT, Device API, Logging and Upgrade settings.
3. Confirm save success and validation failures appear beside the action bar
   without a full-page redirect, and that **Discard changes** restores the
   latest saved values.
4. Add, edit and remove a portal user; edit and revoke an API client; verify
   only the affected workspace refreshes.
5. Exercise certificate validation/renewal and configuration restore. Confirm
   progress remains visible, the affected content refreshes in place and the
   restart banner updates when required.
6. Start a controlled watchdog scenario from Release qualification, verify the
   device recovery independently and record the observed result. Confirm the
   five-step workflow remains visible and the gate/evidence workspace refreshes.
7. Stage and discard a later dummy release, then stage it again and verify
   **Restart and install** becomes available without returning to the beginning
   of the workflow.
8. Check narrow-screen layout, keyboard focus, light/dark themes and the
   unsaved-change warning on editable forms.

Host evidence: 690 automated tests, the MicroPython compatibility contract,
Python compilation and repository architecture gates passed before release.
Device and browser observations must be recorded separately; this plan does not
claim those results in advance.
