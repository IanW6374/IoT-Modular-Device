# IoT-MD v3.0.0-alpha.18 qualification

Alpha 18 uses release sequence `2723` and native platform ABI 6.

## Required observations

1. Install the signed universal artifact and verify both displayed component
   versions finish on Alpha 18 and remain there after restart.
2. Power-cycle with the configured access point available. Confirm a transient
   first association failure is logged as a warning, later attempts continue,
   and the device does not enter recovery unless all three attempts fail.
3. Repeat the power cycle three times and confirm the portal returns with a
   green status LED. Record each controlled power-recovery result explicitly;
   do not infer a passed HIL gate from ordinary boot telemetry.
4. Before and after a same-release power cycle, compare the qualification soak
   start and health/storage counters and confirm they have not reset.
5. Open **Maintenance > Release qualification** and confirm automatic device
   observations and controlled qualification tests have distinct labels. Also
   confirm the Alpha 17 campaign appears under previous release evidence.
6. Open manual upgrade with no selected file and confirm the filename state and
   artifact guidance have clear visual separation.
7. Repeat Alpha 13's universal upgrade, rollback and interrupted-power checks.

No additional greenfield feature gate is introduced by this release. Active-v3
promotion remains blocked until every release-bound gate has passing
hardware-in-the-loop evidence.
