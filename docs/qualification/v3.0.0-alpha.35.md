# Alpha35 upgrade history and qualification retry checks

Release sequence: `2740`. Native ABI: `6`. MicroPython: `1.29.0`.
ESP-IDF: `5.5.5` (unchanged from Alpha34).

## Upgrade page

1. Install the universal package and verify both application and core Alpha35.
2. Open Maintenance > Upgrades > Upgrade. Check the Automatic badge after a
   successful check with and without an available release, and after a failed
   check. No percentage or separate last-check/status metric should be needed.
3. Confirm Upgrade history is visible without expansion. Run a manual check and
   let a scheduled check run. Both should appear with their outcome and version
   where applicable; reboot and confirm the history persists.
4. Stage a signed release without restarting, navigate away and return. Select
   Staged to activate it explicitly or discard it. Keep testing automatic and
   manual universal upgrades, including paired confirmation and rollback.
5. Check desktop and narrow-screen layout. Host Playwright fixtures exercise the
   real CSP but do not replace on-device browser testing.

## Qualification retry

1. Inspect existing evidence after upgrading: migration must preserve failures
   and valid cross-release campaign evidence according to the existing rules.
2. Correct the cause of a failed gate first. As an administrator, expand Restart
   failed test, enter a reason and confirm. It must return to pending observation,
   not pass immediately. Previous evidence must be visible in retry history.
3. For health/storage, complete a fresh full observation window. Check unrelated
   passed gates and general soak evidence remain unchanged. For event-driven
   gates, repeat the required successful tests before expecting a pass.
4. Reboot and confirm both the new test window and archived failure persist.
5. Submit an old retry form after another retry: it must be rejected. Operators
   and viewers must not be able to invoke the administrator action.
6. On a disposable test device, exercise storage/write failure during archival
   and reset. Failure must not silently clear the blocked gate. Do not deliberately
   corrupt or fill production credential storage.
7. Resolve an active canary pause and confirm the live gate clears without a
   retry button. Continue the existing power-loss, network, certificate, peripheral
   and paired-update qualification campaign; host tests do not certify these.
