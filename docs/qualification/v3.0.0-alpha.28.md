# IoT-MD v3.0.0-alpha.28 constrained universal-upload test

Alpha 28 uses release sequence `2733` and native platform ABI 6.

1. On the affected Alpha 26 or Alpha 27 device, install
   `application-3.0.0-alpha.28.iotapp`, activate it and allow the application
   trial to confirm.
2. Confirm Overview reports Application version `3.0.0-alpha.28`; Core may
   still report the preceding release at this bridge point.
3. Upload `universal-3.0.0-alpha.28.iotuni` using **Maintenance > Upgrades >
   Available upgrades**. Confirm the earlier `insufficient storage for
   resumable upload` rejection does not recur.
4. Confirm the workflow skips the already installed application, uploads and
   verifies the core, and reaches **Install upgrade**.
5. Activate the universal upgrade and reboot. Confirm Overview reports both
   Application and Core version `3.0.0-alpha.28` and the status LED is green.
6. Restart and power-cycle once. Confirm the paired release remains selected,
   the portal returns, and Release qualification remains available.
7. Attempt an oversized standalone core recovery upload in a controlled test
   environment. Confirm it is still rejected rather than reclaiming the
   inactive application generation without a signed universal plan.
