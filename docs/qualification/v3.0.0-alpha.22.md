# IoT-MD v3.0.0-alpha.22 qualification

Alpha 22 uses release sequence `2727` and native platform ABI 6. Install IoT MD
Management Suite 2.2.5 before testing the automatic universal workflow.

## Automatic universal upgrade

1. Keep the device on Alpha 21, synchronize the Alpha 22 GitHub release in the
   Management Suite and promote it to Alpha.
2. Check the Alpha channel from **Maintenance > Upgrades**. Confirm the offered
   type is **Universal upgrade**, not Core firmware or Application.
3. Select **Download and stage** and confirm the displayed workflow is the same
   universal workflow used for a manual `.iotuni` upload.
4. Confirm both required components are staged before activation and the action
   reads **Activate universal upgrade 3.0.0-alpha.22 and reboot**.
5. Activate, then verify application and core both report Alpha 22 after health
   confirmation and one additional normal restart.
6. Repeat from a deliberately split Alpha 22/Alpha 21 pair. Confirm the
   universal verifier checks both components, stages only the older component
   and still completes the paired transaction.
7. Present a catalog older than either installed component and confirm no
   component fallback or downgrade is offered.

## Portal and USB regression

1. Confirm the top-level order is Status, Device, Module and Maintenance, with
   **Portal users** inside Maintenance.
2. Confirm existing and new user cards align, **Enabled** defaults on for a new
   user, and clearing it creates a disabled account.
3. Stage an application-only recovery bundle over USB with `--activate`; confirm
   frozen recovery activates and confirms it rather than rolling it back.

Repeat Alpha 21's portal dispatcher, session-expiry and general qualification
checks before accepting this build as a promotion candidate.
