# Alpha 52 qualification campaign

Alpha 52 uses release sequence `2757` and native platform ABI 6.

Status: **host regression passed; awaiting a clean candidate build and hardware
evidence**.

The non-qualifying fault simulation passed 165 tests with no failures, errors
or skips. The signed application, core and firmware-first universal manifests
and payloads have also been verified against the release key. Neither result
closes an on-device qualification gate.

The current artifacts are signed shakedown builds produced from the existing
dirty development tree. They are suitable for proving the test setup, API and
recovery procedures, but not for the final promotion record. Commit the frozen
source, rebuild without `--allow-dirty`, and use that clean artifact sequence
for the formal 48-hour campaign.

## Evidence profile

The `v3-beta` profile requires all 15 gates:

| Gate | Minimum evidence |
| --- | --- |
| Soak | 48 hours on the final release sequence |
| Health | 2,400 samples; no more than 3 consecutive unhealthy samples |
| Storage | 2,400 samples; never below 131,072 free bytes |
| Network recovery | 3 controlled recoveries, each within 300 seconds |
| Certificate renewal | 1 successful managed renewal |
| Paired updates | 3 confirmed signed universal transitions |
| Power recovery | 3 successful physical power interruptions/recoveries |
| Canary health | No active canary pause or health failure |
| Release confirmation | The installed application/core pair is confirmed |
| Native recovery | 3 successful controlled native recoveries |
| Watchdog recovery | 3 successful watchdog recoveries |
| Identity interoperability | 1 successful end-to-end transaction |
| Fleet interoperability | 1 successful signed-command transaction |
| Migration rollback | 1 successful migration and rollback exercise |
| Driver hardware | All 13 supported driver variants on physical fixtures |

Cross-release campaign counters carry forward, but soak, health, storage,
canary and release-confirmation evidence restart for the final installed
sequence. Three paired confirmations therefore require three distinct,
monotonically increasing signed universal bundles. Reinstalling sequence `2757`
or recording a scenario request as success is not valid evidence.

## Campaign preparation

1. Reserve a production-equivalent ESP32-S3 device, serial capture, controlled
   power relay, managed network interruption point and the complete driver
   fixture set.
2. Enrol a dedicated mTLS qualification certificate with `read`,
   `qualification:write` and `qualification:execute` scopes.
3. Retain the pre-campaign portal/API status, boot count, reset cause, running
   application/core versions, release sequences and exported qualification
   evidence.
4. Install `universal-3.0.0-alpha.52.iotuni`. Confirm both components report
   Alpha 52 sequence 2757, the pair reaches healthy confirmation and the prior
   pair remains available for rollback.
5. Confirm ordinary read/write certificates receive `403` from qualification
   mutation endpoints.

## Start the release-bound observation

Use a persistent state directory outside the repository. Substitute the real
device identity and certificate paths:

```sh
python3 v3/host/qualification_runner.py \
  --state /secure/qualification/alpha52.state.json \
  --evidence /secure/qualification/alpha52.evidence.json \
  --device-id DEVICE_ID --version 3.0.0-alpha.52 --sequence 2757 status

python3 v3/host/qualification_runner.py \
  --state /secure/qualification/alpha52.state.json \
  --evidence /secure/qualification/alpha52.evidence.json \
  --device-id DEVICE_ID --version 3.0.0-alpha.52 --sequence 2757 monitor \
  --url https://DEVICE_HOST:8444/api/v2/device \
  --ca-file CA.pem --cert-file qualification.pem --key-file qualification-key.pem \
  --health-path device.qualification_observation.health_state \
  --storage-path device.qualification_observation.storage_free_bytes \
  --duration 172800 --interval 60
```

Start the 48-hour monitor only after the final campaign sequence is installed.
A network probe failure records network-down evidence; it does not fabricate an
unhealthy or low-storage observation.

## Controlled tests

1. Run the watchdog observer three times with unique run IDs and serial logging:

   ```sh
   python3 v3/host/qualification_hil.py \
     --url https://DEVICE_HOST:8444 --ca-file CA.pem \
     --cert-file qualification.pem --key-file qualification-key.pem \
     watchdog
   ```

   Each success must observe a higher boot count, watchdog reset cause and a
   healthy return before evidence is submitted.
2. Run native recovery three times. Observe frozen recovery before replaceable
   application code, restoration of a signed confirmed pair and healthy return.
3. Execute three relay-controlled power cuts at documented paired-update phases
   and verify deterministic recovery without a mixed application/core pair.
4. Interrupt the managed network at least three times and verify recovery within
   300 seconds, including MQTT, portal, API and syslog reconnection.
5. Complete one real managed certificate renewal and verify the renewed identity
   across portal, API and dependent transports.
6. Complete identity, signed fleet-command, migration rollback and all 13
   physical-driver fixture matrices. Submit observed outcomes through the
   qualification API or administrator portal; never submit a desired gate state.
7. Exercise paired trial failure and native rollback separately. Preserve serial
   output, update history and exported evidence for every expected and unexpected
   rollback.

## Supporting checks

Run the authenticated browser suite in Chromium, Firefox, WebKit and both mobile
profiles, then separately validate the production portal certificate and
hostname without bypassing certificate errors. Run the Device API HIL smoke
suite and retain its JSON alongside serial logs, relay timings, browser reports
and the final qualification export.

Promotion remains blocked until the exported record reports
`promotion_ready: true`, the runner exits zero, implementation capability flags
for paired trial/native rollback are true, and every physical observation can
be traced to retained evidence.
