# Alpha 99 transport qualification

1. Install the signed universal Alpha 99 bundle on a Core API 12 device.
   Confirm application/core Alpha 99, sequence 2804 and a confirmed trial.
2. Refresh Management and use Portal/API concurrently. Check that valid mTLS
   still succeeds and unenrolled/wrong-CA clients remain rejected.
3. Repeat rejected TLS handshakes and abrupt disconnects. Confirm valid clients
   continue connecting without steadily consuming internal/DMA memory.
4. In a controlled test, terminate the underlying accept loop. Confirm its
   socket is closed and supervision rebinds without rebooting; API availability
   is false while the listener is stopped. Check restart diagnostic events.
5. Replace an API/portal certificate normally. Confirm the deliberately closed
   listener is not resurrected by the old supervisor.
6. If `EPERM` recurs, retain the stage/errno/internal/DMA diagnostic lines and
   timestamp. Do not change trust or permissions solely because of `EPERM`.

No hardware fault injection or update of IoT-MD-001/002 is performed by the
host validation process.
