# IoT-MD v3.0.0-alpha.31 final portal and qualification-candidate test

Alpha 31 uses release sequence `2736` and native platform ABI 6.

## Installation and operation continuity

1. Install the Alpha 31 universal release from Alpha 30. Confirm Overview shows
   Application and Core `3.0.0-alpha.31` after the paired trial is confirmed.
2. Start an automatic universal download, switch to an unrelated browser tab
   for at least 30 seconds and return. Confirm device progress continued and the
   task did not restart.
3. During another automatic download or managed certificate renewal, refresh
   the task page and navigate elsewhere. Confirm the header indicator links back
   to the same running operation. After completion it must disappear.
4. Start a manual universal upload, switch tabs and return. Confirm the upload
   advances. Attempt to close or navigate away during transfer and confirm the
   browser warns first. Cancel and confirm the warning clears.
5. Create an invalid upgrade-file failure. Confirm controls recover, the portal
   remains usable and **Open device log** opens with the `ERROR` filter applied.

## Portal behaviour and accessibility

6. With only a keyboard, open each top-level menu, move with Arrow keys, enter
   and leave the Certificates/Logging/Upgrades submenus, press Escape and use
   the skip link. Confirm focus remains visible and predictable.
7. Verify Overview and Device log show refresh/check times. Hide each tab for
   at least 15 seconds, return and confirm it refreshes immediately.
8. Change a form without saving and navigate away; confirm the browser warns.
   Submit or discard the change and confirm normal navigation resumes.
9. Verify the portal at 320, 768, 1280 and 1920 CSS-pixel widths, browser zoom
   at 200%, operating-system dark mode, reduced motion and forced/high contrast.
10. Allow an account's idle timeout to expire without navigating. Confirm the
    visible page changes to the signed-out page at expiry.

## Browser and security qualification

11. Run the non-destructive suite in `tests/browser` against the installed
    device. Record the Chromium, Firefox, WebKit, Pixel 5 and iPhone 13 results.
12. Inspect an authenticated HTTPS session. Confirm the cookie is named
    `__Host-iotmd_session` and is Secure, HttpOnly, SameSite Strict and Path `/`.
13. Confirm HTML responses contain a nonce-based Content Security Policy with
    no `unsafe-inline`; confirm fingerprinted portal assets return ETags and a
    matching `If-None-Match` request receives `304 Not Modified`.
14. Separately validate the production portal certificate and hostname with
    certificate errors disabled; the functional browser suite deliberately
    permits a local qualification CA.

## Greenfield hardware gates

15. Execute the full HIL qualification runner and the controlled power, update,
    renewal and validation events documented in `docs/UPGRADE_GUIDE.md`.
16. Complete repeated power interruption at every paired-update transition,
    native recovery, watchdog, resource-conflict, driver restart, network/MQTT,
    certificate renewal, fleet migration, shadow parity and failed-active-boot
    fallback tests.
17. Complete the multi-day health/storage/canary soak. Export the final evidence
    record and verify the runner exits zero before proposing beta promotion.
