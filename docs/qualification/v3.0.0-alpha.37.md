# Alpha 37 controlled qualification API and HIL test

Alpha 37 uses release sequence `2742` and native platform ABI 6.

1. Install the universal release and confirm both components report Alpha 37.
2. Enrol a dedicated qualification client certificate and verify its scopes are
   `read`, `qualification:write` and `qualification:execute`.
3. Verify read-only and ordinary write clients receive `403` for qualification
   mutation endpoints.
4. Record controlled evidence from the administrator portal and API. Confirm
   the gate counter changes once per genuine observation and no caller can post
   a final `passed` state.
5. Execute `qualification_hil.py ... watchdog` three times with serial logging.
   Confirm watchdog reset causes, boot-count advancement and healthy return.
6. Start native recovery with a unique run ID. Confirm frozen recovery starts
   before the replaceable application and restore a signed confirmed pair.
7. Run the simulated campaign and retain its JSON as regression evidence only;
   confirm it does not change any on-device gate.
8. Continue the external relay power-cut, managed-network outage, identity,
   fleet, migration and complete 13-driver physical fixture campaigns.

Do not use scenario acceptance as success evidence. The observer records the
outcome only after verifying the physical result.
