# IoT-MD v3.0.0-alpha.11 qualification

Alpha 11 uses release sequence `2716` and native platform ABI 6.

## Required observations

1. Install the universal artifact from Alpha 10 and verify both displayed
   versions are Alpha 11 during trial and after confirmation.
2. Interrupt power before and after native pair confirmation. Verify the device
   reaches either the complete Alpha 11 pair or the complete previous pair.
3. Force the bootloader to reject the Alpha 11 core after application commit;
   verify frozen reconciliation restores the previous application slot.
4. Force native confirmation to fail after the application commit; verify the
   paired rollback restores the previous application slot.
5. Exercise Cancel before upload, during upload and after verification. No
   cancelled release may become active.
6. Verify the vertical workflow and current-task progress for `.iotuni`,
   `.iotapp` and `.iotcore` files on desktop and narrow layouts.
7. Interrupt migration staging and active-v3 startup; verify orphan handle
   cleanup and the persistent compatibility latch.
8. Repeat the full Alpha 10 hardware, transport, identity, fleet, migration,
   driver, soak and cutover qualification matrices against Alpha 11.

Active-v3 promotion remains blocked until all release-bound evidence passes.
