# Alpha 108: v3-only Device API cutover

This is a coordinated breaking application update with Management 3.0.0.
Install Alpha 108 using each device's portal before upgrading Management.
Use the matching universal release: application startup requires core API 15 /
native ABI 7. Do not install the application alone on core API 14. No fresh
installation, factory flash or data erasure is required.

Verify on hardware before promotion:

1. With an enrolled read-scoped mTLS client, `GET /api/v3` reports protocol 3,
   correct enabled capabilities and configured body limits.
2. `GET /api/v2/device` returns HTTP 410; v2 writes never execute commands.
3. Revoked clients and insufficient scopes remain rejected. Permission and TLS
   failures must not be mistaken for an unsupported protocol.
4. Management 3.0.0 discovers all upgraded devices and polls inventory,
   configuration, health and events. Verify description, profile, encrypted
   backup/restore preview and signed fleet deployment with scoped test clients.
5. Discovery reports persistent idempotency and a next request sequence when
   encrypted operation storage is available. Each POST uses
   `Idempotency-Key: sequence.hex_nonce`; replay returns the existing outcome,
   differing content returns 409, and old evicted sequences cannot execute.
   A pending command interrupted by reset remains uncertain, never replayed.
6. Qualification evidence reports contract 2 and 14 active gates. Historical
   migration observations remain retained, and untested gates remain not-run.

Host regression coverage is not hardware qualification. Preserve current
configuration backups before testing disruptive operations.

Also verify each configured driver on the actual board: resource conflicts,
safe initial outputs, compatible shared SPI, failed-setup cleanup, stale handles,
soft restart, UART IRQ release and DHT/pulse timing. Native qualification flags
remain false until this evidence is observed. SPI IDs are 1/2; GPIOs 0, 19/20,
26–37 and 43/44 are protected. Grove ADC defaults to GPIO 1 on ESP32-S3.
Explicit multiport RS485 configurations must declare each port's TX/RX pins;
single-port configurations retain UART 1 / TX 17 / RX 18 defaults.
