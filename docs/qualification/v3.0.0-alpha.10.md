# IoT-MD v3.0.0-alpha.10 qualification

Status: **awaiting hardware, interoperability and power-interruption evidence**.

Automated host tests and a production-secure ESP32-S3 compile establish the
implementation baseline:

- runtime contract and native platform ABI 6 agree;
- paired journal transitions bind one release, platform partition and runtime
  slot and reject mismatched or premature confirmation;
- frozen recovery can reconcile interrupted pair transitions without importing
  the replaceable product application;
- native jobs/events and physical resources remain bounded;
- all five production transport adapters, production identity, fleet and
  migration services share one composition boundary;
- the shadow implementation performs validation/comparison without transport or
  hardware side effects; and
- all 13 supported module variants translate to declared v3 drivers and native
  resource requirements.

Still required on physical hardware:

- the complete paired-update power-cut matrix and native rollback proof;
- corrupt/missing runtime, watchdog-loop and signed recovery campaigns;
- native queue timeout/saturation/retry testing;
- the complete physical-driver, bus-sharing, interrupt and soft-restart matrix;
- transport parity and reconnect tests;
- certificate enrollment/renewal/trust recovery tests;
- real Management Suite policy/report and representative v2 migration trials;
  and
- shadow-to-active cutover plus persistent compatibility fallback.

Until those observations are signed and attached to release sequence `2715`,
native qualification booleans remain false and active-v3 cutover remains
blocked.
